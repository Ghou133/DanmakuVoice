# 超绝可爱弹幕姬隐私说明

更新日期：2026-10-07。商店发布者显示名称：CurePrism。

超绝可爱弹幕姬是免费开源的 Windows 弹幕接收与语音播报工具。本说明适用于本应用，不替代哔哩哔哩、豆包、Fish Audio 或 Microsoft Store 各自的隐私政策。

## 本地保存的信息

应用通过 Windows Known Folder API 定位当前用户的 `AppData\Local\DanmakuVoice`，保存设置、音色、用户别名、专属声音绑定、播报规则、直播间信息及必要的登录状态。更换 EXE 名称、安装位置和工作目录不改变默认数据目录；显式 `--data-dir` 参数选择的独立目录除外。商店包排除该目录的文件虚拟化，旧包副本不会自动覆盖当前数据库。登录凭据和 API Key 使用 Windows 当前用户范围的 DPAPI 加密保存。普通配置导出不包含这些凭据。应用不会自动导入其他软件或旧数据副本的登录凭据。

启用开播台后，应用按登录账号 UID 和自己的直播间保存本机观察的当前场次与上一场摘要，包括已接收消息数量、观察时间及可确认的时长。摘要不含消息正文或凭据，不进入配置导出，不上传给开发者；应用重启后恢复，清除应用数据会删除。它不是 B站完整直播历史，无法确认的时长不显示。

发送面板读取当前登录账号的个人表情列表及自己直播间的表情列表，包括包名、封面、图片和原始文字标记。表情资料只在当前进程保留，不导出登录凭据；点击表情即单独提交该表情，不改写输入框草稿。个人表情发送前重新读取当前账号的包和条目，按条目的原始文字标记提交；直播独立表情按平台 token 提交。

## 网络请求与第三方服务

- 连接哔哩哔哩直播间时，应用会向哔哩哔哩请求登录／直播间信息并接收弹幕。弹幕可能包含用户昵称、UID、消息正文、头像／表情资料和直播事件；界面可从限定的哔哩哔哩 CDN 加载头像与表情图片。接收弹幕必须扫码登录哔哩哔哩；匿名连接已经关闭。实验性开播台启用后，直播间管理只在点击按钮后提交禁言、直播拉黑或房管任免请求；账号身份、房间和权限由 Rust 端复核。主界面发送文字或独立表情时，只将本次提交内容发往登录账号自己的直播间；不自动发送草稿，不自动重试，也不把发送草稿写入数据库或导出。
- 接收会话运行时，应用约每 30 秒向哔哩哔哩公开接口请求在线观众人数与部分用户资料，滚动到名单末尾时请求下一页。资料包括公开昵称、UID、头像、粉丝牌、大航海和贡献值；榜单请求不携带账号凭据，名单仅保留在当前进程内存，不写入数据库、日志或配置导出。在线名单只包含 B站公开的部分在线观众。
- 使用豆包或 Fish Audio 合成语音时，应用会把待播报文本及所选音色参数发送给你选择的服务。根据播报规则，文本可能包含弹幕正文、用户名或自定义文字。相关请求可能携带该服务的登录凭据或 API Key。
- 使用本地 dots.tts 或 GPT-SoVITS 时，合成文本、音色参数及按服务要求提供的参考音频信息会发送至你配置的服务地址。远程地址会将请求发送至对应远程服务。
- 外部服务可以接收到连接所必需的 IP 地址和请求信息，适用各自政策：[哔哩哔哩](https://www.bilibili.com/)、[豆包](https://www.doubao.com/)、[Fish Audio](https://fish.audio/)。请在相应服务网站查阅当前隐私政策与使用条款。
- 实验性的 OBS 叠加层默认关闭。启用后，应用只在本机回环地址 `127.0.0.1` 上提供带随机令牌的叠加层页面，不向外网开放、不经过任何服务器。页面会显示弹幕、礼物、醒目留言、大航海内容及哔哩哔哩头像；观众名字默认只在礼物和醒目留言旁显示。叠加层画进直播或录像后，观众即可看到这些内容，请按自己的直播需要选择显示项目。
- 商店版通过 Microsoft Store 管理安装和更新。旧版或从源码构建的非商店版本在你点击检查更新时访问 GitHub 的公开版本接口，不上传账号、凭据或安装路径。

## 开发者收集与分享

本应用不内置开发者运营的数据收集服务器、广告或使用行为统计，不自动向开发者发送弹幕、登录凭据、录音或错误日志。用户主动在 GitHub 提交的问题及附件会按 GitHub 的设置公开，请勿上传 Cookie、API Key、整个数据目录或他人的私人信息。

## 控制与删除

你可以在直播间设置停止接收、在主界面停用播报、删除服务连接，或在“设置 → 数据与关于”清除应用数据。配置导出、迁移及开机启动均由用户操作触发。清除应用数据会删除本应用保存的凭据、设置、托管音效、备份及 WebView2 网页缓存；未知文件和外部参考音频／音效原始文件由用户管理，不随应用数据清除。第三方服务保存的信息需要通过对应服务管理。

实验性的开播台默认关闭；用户在“设置 → OBS 与开播 → 开播台”启用后，复用主动扫码获得的 B站登录凭据，读取当前登录账号自己房间的状态（前台可见时约每 60 秒一次），并只在用户点击后发送标题、分区和开播/下播请求。推流信息仅保留在当前进程内存，不进入数据库、日志或配置导出；手动显示后关闭推流面板或设置会清除界面的明文，手动复制会写入 Windows 剪贴板。人脸验证二维码由 B站接口提供或由 B站指定的验证地址生成，只有需要验证时显示，程序不接收人脸图像。开启“OBS 联动”后，弹幕姬只在点击开播、下播、启动 OBS、测试连接或叠加层“添加到 OBS”时连接用户填写的 OBS WebSocket 地址（默认本机 `127.0.0.1:4455`），把推流服务器和推流码写入 OBS 并开始/停止推流，或在当前场景添加/更新叠加层浏览器来源（地址含叠加层令牌）；OBS 设在本机且未运行时，开播或“启动 OBS”会启动用户电脑上的 `obs64.exe`（读取 OBS 安装器写入的注册表项定位）；OBS WebSocket 密码以 Windows DPAPI 加密保存在本机数据库，不进入配置导出、快照或日志。详见 [开播管理](BROADCAST.md)。
