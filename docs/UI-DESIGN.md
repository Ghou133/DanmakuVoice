# 现有界面设计与验收

本文以当前 `crates/desktop/ui` 与 Tauri 窗口代码为准，维护现有设计，不是再次改版的计划。架构入口为 [ARCHITECTURE.md](../ARCHITECTURE.md)，命令契约为 [UI-IPC.md](UI-IPC.md)，实际验证记录只保留在 [PROGRESS.md](../PROGRESS.md)。

## 设计基线

- 产品名“超绝可爱弹幕姬”；文件名、内部标识与数据目录沿用 `DanmakuVoice`。Logo 原图与处理说明见 [图标说明](../crates/desktop/icons/README.md)。账号资料在直播间设置展示，消息头像只使用实际事件提供的资料，缺失时显示文字标识。
- Tauri 2 / 系统 WebView2，本地 HTML、CSS、JavaScript 明确列入 `frontendDist` 并嵌入程序；不嵌入测试、源图、Node.js 或开发服务器。窗口 1040×740，最小 780×580，自绘可拖动标题栏，双击最大化，保留阴影及主题匹配的启动背景。
- 夜幕／晨雾色板，粉—紫—蓝渐变强调色；刊头、聚光文字使用内置的 DanmakuVoice Serif SC（Noto Serif CJK SC 子集，GB2312 全部汉字 + 界面用字，Medium/Bold/Black 三档，400 与 500 共用 Medium），子集外的字逐字回退到系统衬线字体；数字仍用现有衬线字体，`font-synthesis:none`。布局、字体、美术、透明度、阴影、动画时长／曲线与交互反馈均为保留基线。
- 欢迎页之后选择“扫码登录／输入主播 UID”，再选择豆包朗读或只看弹幕，最后汇总并开始接收；欢迎页不请求二维码。匿名 UID 是主播 UID，不是房间号。完成引导后启动只尝试连接已保存的直播间，禁网测试不自动连接。
- 主界面以 LIVE 状态及直播间刊头、单栏弹幕、聚光卡片和控制坞组成。连续同一观众消息合并，间隔至少五分钟插入时间分隔；翻看历史时取消渐隐。聚光进度按文字长度估算，不能当成真实音频进度。
- 控制坞有音色、静音与音量、待播列表、播报开关。浏览服务不改变直播声音；选择音色才保存，试听发起真实合成。选择待播条目调用 `queue.jump`；关闭播报仍接收弹幕。当前主页没有旧版跳过、清空或停止按钮，相关后端命令仍保留。
- 点击弹幕打开观众卡片，可编辑名字读法及专属音色；已有专属声音显示标签。用户名与正文词典分开处理，原始弹幕显示不会被播报替换词改写。
- 设置是整窗页面，分类为直播间、声音、播报内容、音效、开播与 OBS 叠加层（两者相邻，均标“实验”）、通用、数据与关于。保留现有平铺卡片、胶囊、渐变开关与分类移动指示，旧分类 ID 映射保留。输入自动防抖保存，选择器立即保存；切页及关闭设置前收敛编辑，编辑期间无效或失败草稿留在编辑器并提示，不覆盖有效配置。退出会尝试收敛自动编辑并直接清理退出，失败不阻止关闭；账号／导入等显式表单不会自动提交。

## OBS 叠加层（实验性）

给看直播和看录播的观众看的弹幕层，美观优先于占屏面积。2026-10-03 用户在 Claude Design 画板中逐项确认：

- 两种样式由用户二选一：“光脊”（默认，一条发光竖线串起刊头和弹幕，无底板）与“一体卡”（刊头和弹幕收进一张玻璃卡片）。位置四角可选，大小 50%–200%，暗角深浅可调。
- 常驻刊头（M2）：英文 kicker `● LIVE · SAT 21:04`（Instrument Serif），可自定义标题（默认“今晚的弹幕”，≤12 字），短渐变线，英文斜体副标题跟随真实状态：`now reading.`、`N words tonight.`、关闭播报时 `danmaku only, tonight.`、断线时 `reconnecting…`；冷场时显示用户自定义副标题，留空用 `say a word — it'll be read aloud.`。不显示分区和开播时长，kicker 与副标题不放中文。
- 观众名字默认不显示，只在礼物、醒目留言、大航海旁显示。正在朗读的一条做聚光：文字按朗读进度点亮，进度线上有彗星光点，头像外圈旋转；读完 1.6 秒后降为小行。每条新消息只扫一次光，聚光光晕缓慢呼吸。重复弹幕合并为“×N”，礼物数量用斜体数字。
- 醒目留言独立显示在画面上方正中，是一张“金券”，按价格分月白（<¥50）、香槟金（¥50+）、玫瑰金（¥500+）、绯红（¥1000+），显示时长按 B 站档位，结束后折成票根。
- 所有尺寸按 1920×1080 设计稿乘 `min(宽/1920, 高/1080)×大小`，因此 1080p、2560×1600、3840×2160、3840×1728 都由 OBS 浏览器来源的实际宽高缩放。页面不用 `color-mix` 等新语法，兼容 OBS 自带的较旧 CEF。
- 设置页提供预览：比例自动跟随 OBS 报告的画布（未连接时按 1920×1080），按真实比例缩放，不提供手选比例；预览下方三个小色点切换抽象背景（深色／亮色／透明），用来检查亮画面上的可读性和暗角，不影响 OBS 输出；预览不使用任何真实游戏画面。地址只显示打码后的令牌，复制时才给完整地址。

## 开播台（实验性）

2026-10-03 按用户要求重做另一名 agent 放在“直播间”页里的开播按钮组：开播与 OBS 叠加层是同一批主播用的实验功能，所以开播成为独立的实验分类，紧挨 OBS 叠加层，页头沿用叠加层的“标题＋实验性＋启用开关”。旧的“设置 → 直播间 → 开播管理”区块已移除。

- 未启用时，设置页只展示开播台的抽象预览和三条用途说明，不读取账号或房间；启用后才出现状态卡、直播信息、人脸验证和“推流到 OBS”。
- 启用并扫码登录后，主界面右上角出现开播台，与左侧刊头左右对称：右对齐的英文 kicker（`OFF AIR`／`ON AIR` 加 Instrument Serif 计时／`REPLAY`）、衬线标题和分区，右侧是钥匙按钮（推流面板）与主按钮。主按钮未开播时是粉紫渐变“开播”（圆点录制符号），直播中变为玻璃底“下播”（红色方块）；“ON AIR”用独立的直播红 `--lv-air`，带缓慢的计数灯扩散环，开播台背后有一团很淡的红色光晕。左侧刊头仍表示弹幕接收（`LIVE`），右侧只表示 B站房间是否开播。
- 点标题、钥匙或开播后弹出同一个玻璃面板（从右上角展开）：直播信息、推流到 OBS（服务器／推流码遮住，复制、显示、清除，三步 OBS 指引）、人脸验证（二维码＋继续开播）。开播成功后自动打开推流面板；下播先确认。面板外点击或 Esc 关闭，有未保存的标题修改时不会被误关。
- 刊头在开播模式下为右侧预留空间，名字过长时省略；780 px 最小窗口和英文下不重叠、不横向滚动，英文按钮不用中文字距。

## 动画与状态边界

弹幕重排使用 FLIP 位移，聚光行从正文 22 px 连续收回到 15 px，以现有 520 ms 归位；没有旧版脱离副本或正文余晖淡入。`leaveGhost` 用于弹窗、面板及提示条退出，主题通过 View Transitions 扩散；声音渐变圈仅朗读时流动，空状态波纹随连接状态变化。保留当前缓动与轻回弹，不能用降低帧率、删除动画、简化阴影或有损资源处理换取性能。优化放在未变化状态、重复计算、无效重绘和加载过程。

`motionAllowed()` 遵循减少动态效果和现有后台行为。失焦、隐藏、最小化时停止前端轮询与动画，WebView2 内存目标设为 Low；恢复为 Normal 并刷新。Rust 接收、排队和播放不依赖界面可见性。设置打开时不重绘被遮挡的聊天，关闭后补齐安全快照。

凭据、SQLite、网络、规则、队列与设备生命周期由 Rust 拥有。前端只展示快照及编辑草稿，弹幕按文本和经限制的 CDN 表情渲染，不执行消息 HTML。清除数据先确认 WebView2 缓存清理完成，再重置本应用管理的数据；不删除用户指定目录中的未知文件或外部参考音频。

## 验证范围

使用独立 `--data-dir`，必要时加 `--disable-network`；禁网标志拒绝真实网络命令，不制造登录或弹幕。自动化浏览器夹具只用于页面、输入、状态和动画对照，虚构消息必须标明，不能证明真实直播、原生 WebView2 或物理播报。

视觉检查应覆盖两套主题、引导、主页、音色面板、观众卡片、七个设置分类及确认框、键盘／IME、最小窗口和缩放。动画需观察连续帧或录制，静态截图只证明布局。原生首次显示、托盘／恢复、真实扫码、持续播报和外接音频设备分别验收；不能运行的项目记录未验证。

性能对照使用同机、相同 target／profile／feature 和相同负载，包含 WebView2 子进程。`scripts/measure-runtime.ps1` 按 PID 与启动时间累计 CPU 样本增量；两次采样之间完整生灭的子进程仍不可观测，CPU 百分比按单核心表示。WebView2 Runtime 的部署体积独立于程序与必需发行包。
