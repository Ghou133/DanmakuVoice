# 开播（实验性）

开播台和 OBS 叠加层一样是实验性功能，默认关闭。两者在同一个设置分类：**设置 → OBS 与开播**。页面顶部是共用的“OBS 连接”，下面两张卡片切换“开播台”和“叠加层”，各有自己的“启用”开关。开播台启用前只显示它的样子，不读取任何账号或房间信息。

需要先在弹幕姬扫码登录自己的 B站账号。开播台只管理登录账号自己的直播间；旧配置中的房间也不会被当作开播目标；匿名模式与主播 UID 选择入口已经关闭。

## 主界面开播台

主界面左上保留星期刊头、日期时间和「用户名的直播间」，人数为零时隐藏人数入口。启用后，右上显示开播状态与操作：

- 小字状态：`OFF AIR`（未开播）、`ON AIR` 加已开播时长（直播中）、`REPLAY`（轮播中）。时长取自 B站返回的开播时间，按秒走表。
- 直播标题与分区。点击标题直接在天空编辑（最多 40 字，带字数）和大分区/子分区，点“保存”或按 Enter 提交；Esc 或点击背景丢弃，输入法候选确认不会提交。
- **开播**：用当前保存的分区开播；启用 OBS 联动后自动配置推流信息并让 OBS 开始推流。右上角不再展示推流码，OBS 出错时提示到「设置 → OBS 与开播」检查。
- 需要人脸验证时（B站错误码 60024 / 60043），面板显示验证二维码；用哔哩哔哩 App 扫码完成后，点“继续开播”。程序不会自动重试。
- OBS 视频码率入口在「设置 → OBS 与开播」的显式展开区域；主界面及设置已去掉叠加层标题编辑。码率读取 OBS 当前配置文件，简单输出模式可保存 100–100000 Kbps；直播中也可保存，下次启动推流编码器生效，不停止当前推流，不宣称实时更改当前编码器。高级输出模式请到 OBS「设置 → 输出 → 推流」调整。
- **下播**：点一下即下播，不再弹确认框。开启“OBS 联动”时先让 OBS 停止推流再关闭直播间；未开启时请自己在 OBS 停止推流。下播只关闭 B站直播间，弹幕接收和播报照常。退出弹幕姬不会自动下播。
- 未登录时开播台显示“扫码登录”，跳到“设置 → 直播间”。
- 开播前仅在存在本机保存的上一场摘要时显示统计；没有记录时湖面留空。摘要按账号与自己房间隔离，重启后恢复，只包含本机实际接收的消息和可确认时长，未知时长省略。

## 设置 → OBS 与开播 → 开播台

同一套操作的完整版：状态卡（状态、时长、房间号与分区、刷新、在浏览器打开直播间、开播/下播）、“直播信息”（标题和分区，开播时如有未保存的修改会先保存）、人脸验证、“推流到 OBS”和“OBS 联动”。关闭开关后主界面不再显示开播台，也不再读取开播状态；内存中的推流信息保留到下播、清除、换号或退出程序。

## OBS 联动

让弹幕姬的开播/下播同时控制 OBS，不用再手动复制推流码。需要 OBS 28 或更高版本（自带 obs-websocket 5）。

1. 在 OBS 打开“工具 → WebSocket 服务器设置”，勾选“开启 WebSocket 服务器”。默认端口 4455；如开启了身份验证，点“显示连接信息”可看到密码。
2. 在弹幕姬“设置 → OBS 与开播”顶部的“OBS 连接 → 连接设置”里，地址保持 `127.0.0.1`（OBS 在另一台电脑时填那台电脑的局域网地址），端口与 OBS 一致，需要时填写密码并点“保存密码”，再点“测试连接”。“OBS 程序”默认从安装信息（注册表 `HKLM\SOFTWARE\OBS Studio`）、`Program Files\obs-studio` 或 Steam 默认库自动找到 `obs64.exe`；便携版可手动选择，只接受名为 `obs64.exe` 的程序。
3. 在“开播台”卡片的“OBS 联动”里打开“开播、下播时同步控制 OBS”。“OBS 没开时自动启动”默认开启，只在 OBS 设在本机时有效。
4. 之后点 **开播**：OBS 没在运行就先启动它（工作目录为 OBS 自己的程序目录，退出弹幕姬不会关闭 OBS），同时开好 B站直播间、取得推流码；等 OBS 的 WebSocket 就绪（最多约 45 秒），把 OBS 当前配置的推流服务改为“自定义”并填入服务器和推流码，然后让 OBS 开始推流。OBS 已经在推流时不改动它的设置。连接卡上的“启动 OBS”按钮也可以单独启动并检查。
5. 点 **下播**：先让 OBS 停止推流（最多等约 6 秒让输出结束），再关闭直播间。下播不会关闭 OBS。

OBS 没打开、密码不对等问题不会让开播失败：直播间照常打开，界面提示原因（`DV-OB01`–`DV-OB10`，见 [错误码](ERROR-CODES.md)）并提示检查 OBS 连接设置；设置页仍保留必要时手动复制的入口。下播时 OBS 出错也会继续关闭直播间，并提醒到 OBS 手动停止。

注意：开播会覆盖 OBS 当前配置文件里的“直播 → 服务”设置（改为自定义 RTMP）。OBS 启动时如果弹出“安全模式”等提示窗口，需要先在 OBS 里处理，否则会等到超时（`DV-OB10`）。OBS 设置页可见且在前台时会自动检测连接，最多每 15 秒一次；切走或关闭停止检测。“尚未检测”与实际连接失败分开，失败显示具体原因。WebSocket 连接和叠加层浏览器画面也是两个独立状态，不订阅 OBS 事件、不读取画面。WebSocket 密码用 Windows DPAPI 加密保存在本机数据库，不进入配置导出；推流码只经本机内存发给 OBS。

## 叠加层一键添加到 OBS

“叠加层”卡片启用后，连上 OBS 时点“添加到 OBS”：读取 OBS 的基础画布分辨率和当前节目场景，新建名为“弹幕姬叠加层”的浏览器来源（宽高等于画布）放进该场景；已有受管来源时只更新变动的地址和宽高，若不在当前场景则加入，已有隐藏项会启用。重复点相同地址和尺寸不刷新浏览器。

程序启动、叠加层启用、端口回退或重新生成地址时，会尝试同步已有的受管来源。测试或启动 OBS 成功，以及设置页检测到稍后打开的 OBS 时，也会恢复已有来源。自动恢复不新建、不加入场景、不启用隐藏项，也不启动或停止 OBS 推流；缺少来源会提示点“添加到 OBS”。同名非浏览器来源或指向其他网页的来源不会覆盖（`DV-OB12`）；本机叠加层地址不能直接用于其他电脑的 OBS（`DV-OB13`）。OBS 的“不可见时关闭来源”和“场景激活时刷新”选项保留，手动复制地址仍可使用。

光脊样式的普通弹幕不会因空闲消失：保持最多 4 条小行加 1 条当前聚光，播报完成 1.6 秒后仍按原样缩小，超额移出旧条。临时重连、OBS 浏览器来源刷新可恢复本场内容，恢复旧条不重新播报；连续醒目留言也不会挤掉普通行的恢复缓存。明确停止／重建弹幕接收、切账号或房间会清空；成功读取到正在接收的自有直播间下播、重新开播或真实开播时间改变时也清空，未确认状态不推断新场。缓存只在当前程序内存中保存，退出程序不保留。一体卡和醒目留言仍沿用各自的到期规则。

## 读取频率与隐私

启用期间，主界面或开播设置页在前台可见时，弹幕姬读取一次自己房间的状态，之后约每 60 秒一次（只读）；窗口在后台、请求进行中或离线测试窗口不读取。标题、分区、开播、下播都只在点击后提交，网络失败不会自动重放，请先刷新确认结果。

推流信息只存在于当前进程内存，不写入数据库、日志、配置导出或迁移材料（开启 OBS 联动时会经 obs-websocket 写入 OBS 自己的配置文件，这是 OBS 的正常推流设置）；普通快照只有 `has_stream_key`。只有手动“显示”或“复制”才通过临时命令取回明文，界面接收快照前即移除；关闭设置会清空显示的明文。手动复制会把所选内容写入 Windows 剪贴板。

## 实现

OBS 联动位于 `crates/engine/src/obs.rs`，按 obs-websocket 5.x 公开协议独立实现（Hello/Identify 两步 SHA-256 鉴权，`GetStreamStatus`、`SetStreamServiceSettings`、`StartStream`、`StopStream`、`GetVersion`），复用已有的 tokio-tungstenite、sha2、base64，未新增依赖。B站协议实现位于 `crates/engine/src/broadcast.rs`，使用 Rust 的 reqwest、serde 和 MD5 实现请求、表单编码和应用签名；不需要安装 OBS 插件、Qt、Python 或 Node.js。界面只负责展示和提交命令。画面采集、编码与推流由 OBS 负责。

功能及协议参照 [Zarosmm/obs-bilibili-stream](https://github.com/Zarosmm/obs-bilibili-stream)，核对的源码为 [051cf769d63a9b7111382f3f6cf7baaed0257b05](https://github.com/Zarosmm/obs-bilibili-stream/tree/051cf769d63a9b7111382f3f6cf7baaed0257b05)。本项目独立实现 HTTP 协议，未复制或链接该项目的 C++、Qt、OBS SDK 代码。

协议包含登录账号 UID → 房间解析、房间所有者复核、开播时间、实时分区列表、带 CSRF 的标题/分区更新和关播、查询当前直播客户端版本、签名开播，以及错误码 60024 / 60043 的人脸验证处理。重复管理请求会被拒绝；账号变更会取消等待并拒绝写回过期状态。

这是 B站网页/桌面客户端接口，平台可能改变接口或对账号要求实名认证、开播权限等。当前验收证据与尚未验证的真实账号操作见根目录 `PROGRESS.md`。


## 头像卡片中的直播间管理

仅在实验性「开播台」启用时，点击弹幕或观众名单中的头像，原有别名和声音设置下方加入「直播间管理」：禁言／解除禁言、直播间拉黑／解除拉黑、设为房管／撤销房管。OBS 叠加层开关不会开放管理功能；发送弹幕与表情独立于这两个开关。打开卡片只读取权限与状态；点击按钮才提交。禁言提供本场、1 小时、24 小时、7 天和永久。房管任命仅使用普通房管级别，不能通过本入口授予高级房管。

操作目标是当前选择／接收的直播间，不会自动切换成账号自己的开播房间。登录账号必须为该房间的主播或具备相应权限的房管；普通房管可禁言，直播拉黑要求主播或核实的高级房管，任命／撤销房管只对房主开放。神秘人、未知 UID、自身和主播 UID 不允许这些操作。接口失败显示真实错误，未知状态不视为未禁言／未拉黑，不自动重试写入。

这里的黑名单是主播的直播黑名单，和账号关系黑名单、软件本地播报过滤分开。权限、名单与待处理操作只在内存中保留；关闭开播台、换号、换房间、退出或清除数据会使旧操作失效。

## 主界面发送弹幕与表情

接收个人表情时，平台有时只返回 `[包名_表情]` 文本，不带直播独立表情的类型或图片。接收会话启动前读取当前账号的个人表情资料，表情面板刷新也会更新同账号、同房间的内存目录；只有与平台条目准确匹配且图片地址合法的标记才补为图片。原弹幕正文保留，普通方括号文字不会被误判。纯表情或多个表情组成的一句遵循「过滤 B站官方表情」开关，开启时只展示、不进播报；混合文字、普通 emoji 和未知标记维持原规则。读取失败显示实际错误，可打开表情面板重试；账号或房间切换不沿用旧目录。刷新也会补齐已接收消息的图片，保持原播报结果，不重新排队或重放旧句动画。主画面、历史、观众最近发言、播报任务与 OBS 使用收到的图片资料显示。

主界面底部的发送输入框不依赖直播模式，关闭开播台也可发送。文字弹幕按回车或点「发送」提交；中文输入法的候选确认不会发送。发送只作用于扫码登录账号自己的直播间，由 Rust 端重新核实账号、房间所有者与平台返回的长度限制，长度按网页的 UTF-16 规则计算。账号未登录或离线测试窗口禁用发送。

发送区首次具备登录和网络条件时读取一次长度限制与表情资料；读取失败显示错误，切换窗口不会自动重试。点「表情包」可重新读取当前房间可用表情。所有表情点击后立即单独发送，输入框草稿和选区保持原样；无权限表情显示但禁用。发送失败保留文字草稿，不自动重试，也不生成虚假的本地弹幕。请求使用当前网页的 WBI 查询签名和 CSRF multipart 表单；读取或签名失败即报错，不退回未签名发送。协议核对 [官方播放器 SDK](https://s1.hdslb.com/bfs/static/bilibili-live-player/room-player.01626800.prod.min.js)与[官方发送区／表情代码](https://s1.hdslb.com/bfs/static/blive/blfe-live-room/static/js/9649.1063b9e512e83582c1bc.js)。接口确认不等同于弹幕已在接收流中出现；非空异常确认字段显示未确认，不生成本地回显。

表情面板先显示登录账号个人表情包，再显示直播房间包，各来源内部保持平台顺序，包数量和内容按当前账号实际数组变化。切包只用真实封面图片，选中包全部表情连续纵向滚动，不分页；界面不显示包名、表情名、数量、页码或悬停文字。真实名称保留于数据和无障碍标签。个人表情发送前重新读取当前账号的包和条目 ID，按该条目的原始 `[包名_表情]` 独立提交一条普通消息；不将标记写入输入框，不把个人 ID 当作直播独立图片 token。直播独立表情仍按平台 token 发送并重新核实权限。个人列表协议核对[当前 B站官方评论组件](https://s1.hdslb.com/bfs/seed/jinkela/commentpc/bili-comments.js)使用的 `/x/emote/user/panel/web?business=reply`。缺少可用封面时选用包内首张合法图片，再缺失则显示无文字缺图图形；读取失败在输入状态明确提示，登录过期不保留旧数据。切账号或房间会清空旧包并重新读取，旧请求不能覆盖新账号资料；刷新重排保留选中包及同包滚动位置，主动切包回到顶部。面板使用主界面的日夜玻璃配色和柔和悬停效果。

## 核对过的其他网页接口

当前官方网页还包含房管名单、禁言／直播黑名单管理、全房间禁言规则、服务端屏蔽词、直播公告、封面与标签管理、直播回放管理。除本节明确实现的头像卡片操作外，其余尚未加入软件。参考 [官方直播间代码](https://s1.hdslb.com/bfs/static/blive/blfe-live-room/static/js/app.3b48f866e1563d25d39c.js)、[官方直播中心代码](https://s1.hdslb.com/bfs/static/blive/blfe-link-center/static/js/app.1798ec0bcd4d3bc123e0.js)及[房管级别代码](https://s1.hdslb.com/bfs/static/blive/blfe-link-center/static/js/206.3e171eba31c5620fa1d9.js)及[头像菜单与 AddBlack 参数](https://s1.hdslb.com/bfs/static/blive/blfe-live-room/static/js/438.8fa97186cca171b1035d.js)。这些是网页内部接口证据，不是官方开放接口的稳定性承诺或真实账号验收。

码率实现核对 [obs-websocket 协议](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md)与 OBS 的配置参数实现：只通过 `GetProfileParameter`／`SetProfileParameter` 保存简单输出配置，不调用活动编码器更新。用户选择保留纯 WebSocket，不加入 Lua 脚本。
