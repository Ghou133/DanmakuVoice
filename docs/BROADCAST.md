# 开播（实验性）

开播台和 OBS 叠加层一样是实验性功能，默认关闭。入口：**设置 → 开播**，打开右上角的“启用”。启用前，设置页只显示开播台的样子，不读取任何账号或房间信息。

需要先在弹幕姬扫码登录自己的 B站账号。开播台只管理登录账号自己的直播间；即使弹幕正在接收其他主播（主播 UID 模式），也不会把那个房间当作开播目标。

## 主界面开播台

启用后，主界面右上角出现与左侧刊头对称的开播台：

- 小字状态：`OFF AIR`（未开播）、`ON AIR` 加已开播时长（直播中）、`REPLAY`（轮播中）。时长取自 B站返回的开播时间，按秒走表。
- 直播标题与分区。点击标题打开“直播信息”，可以改标题（最多 40 字，带字数）和大分区/子分区，点“保存到 B站”才会提交。
- **开播**：用当前保存的分区开播。成功后自动弹出“推流到 OBS”，可分别复制服务器和推流码，按面板里的三步填入 OBS（设置 → 直播 → 服务：自定义），再在 OBS 中开始直播。
- 需要人脸验证时（B站错误码 60024 / 60043），面板显示验证二维码；用哔哩哔哩 App 扫码完成后，点“继续开播”。程序不会自动重试。
- 钥匙按钮随时打开推流面板。推流码默认遮住，“显示”后关闭面板即清除；“清除”丢弃本次运行保存的推流信息，不会下播。重启弹幕姬后如仍在直播，可点“重新获取推流码”。
- **下播**：先在 OBS 停止推流，再点下播并确认。下播只关闭 B站直播间，弹幕接收和播报照常。退出弹幕姬不会自动下播。
- 未登录时开播台显示“扫码登录”，跳到“设置 → 直播间”。

## 设置 → 开播

同一套操作的完整版：状态卡（状态、时长、房间号与分区、刷新、在浏览器打开直播间、开播/下播）、“直播信息”（标题和分区，开播时如有未保存的修改会先保存）、人脸验证、“推流到 OBS”。关闭开关后主界面不再显示开播台，也不再读取开播状态；内存中的推流信息保留到下播、清除、换号或退出程序。

## 读取频率与隐私

启用期间，主界面或开播设置页在前台可见时，弹幕姬读取一次自己房间的状态，之后约每 60 秒一次（只读）；窗口在后台、请求进行中或离线测试窗口不读取。标题、分区、开播、下播都只在点击后提交，网络失败不会自动重放，请先刷新确认结果。

推流信息只存在于当前进程内存，不写入数据库、日志、配置导出或迁移材料；普通快照只有 `has_stream_key`。只有手动“显示”或“复制”才通过临时命令取回明文，界面接收快照前即移除；关闭面板或设置会清空显示的明文。手动复制会把所选内容写入 Windows 剪贴板。

## 实现

协议实现位于 `crates/engine/src/broadcast.rs`，使用 Rust 的 reqwest、serde 和 MD5 实现请求、表单编码和应用签名；不需要安装 OBS 插件、Qt、Python 或 Node.js。界面只负责展示和提交命令。画面采集、编码与推流由 OBS 负责。

功能及协议参照 [Zarosmm/obs-bilibili-stream](https://github.com/Zarosmm/obs-bilibili-stream)，核对的源码为 [051cf769d63a9b7111382f3f6cf7baaed0257b05](https://github.com/Zarosmm/obs-bilibili-stream/tree/051cf769d63a9b7111382f3f6cf7baaed0257b05)。本项目独立实现 HTTP 协议，未复制或链接该项目的 C++、Qt、OBS SDK 代码。

协议包含登录账号 UID → 房间解析、房间所有者复核、开播时间、实时分区列表、带 CSRF 的标题/分区更新和关播、查询当前直播客户端版本、签名开播，以及错误码 60024 / 60043 的人脸验证处理。重复管理请求会被拒绝；账号变更会取消等待并拒绝写回过期状态。

这是 B站网页/桌面客户端接口，平台可能改变接口或对账号要求实名认证、开播权限等。当前验收证据与尚未验证的真实账号操作见根目录 `PROGRESS.md`。
